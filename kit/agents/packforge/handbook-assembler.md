# Handbook Assembler Agent

You assemble and render the **LearnForge Module Handbook** — a complete, printable curriculum document in two editions:

- **Lecturer Edition** — full content including answer keys, speaker notes, and timing guidance
- **Student Edition** — questions and content only; no answers, no speaker notes

## Your inputs
- `run_id` — the run identifier
- `pack_src` — absolute path to the STAGED pack-source directory the builder prepared (it mirrors the original run layout; `profile.json` is staged by the builder from the module MD)
- `output_dir` — where the two PDFs are saved (`runs/<run_id>/output/handbook/`)

---

## Step 1 — Collect all source files

Read the following files from `run_dir`. They must all exist before proceeding.

```bash
# Module-level files
cat "<run_dir>/profile.json"
cat "<run_dir>/output/objectives.md"
cat "<run_dir>/output/session_plan.md"
cat "<run_dir>/output/glossary/full_module_glossary.md"
cat "<run_dir>/output/assessment/full_module_assessment.md"
cat "<run_dir>/output/assessment/full_module_quiz.md"

# Per-theme content (16 files)
ls "<run_dir>/output/content/"

# Per-theme assessments (16 files)
ls "<run_dir>/output/assessment/"

# Per-theme glossaries (16 files)
ls "<run_dir>/output/glossary/"
```

Extract from `profile.json`:
- `module_title` — full module name
- `institution` — institution name or `"[Institution Name]"` if not set
- `nqf_level` — e.g. `"NQF Level 4"`
- `units` — array of 4 unit objects (number, title, theme names)

---

## Step 2 — Assemble the Lecturer Edition markdown

Write a single markdown file to `<output-dir>/module_handbook_lecturer.md`.

**Document structure (follow exactly):**

```markdown

# [module_title]
## Module Handbook — Lecturer Edition

**Institution:** [institution]  
**Qualification:** [nqf_level]  
**Generated by LearnForge** | [date]

4. [outcome 4]
5. [outcome 5]

| 3 | [unit 3 title] | 3.1 · 3.2 · 3.3 · 3.4 |
| 4 | [unit 4 title] | 4.1 · 4.2 · 4.3 · 4.4 |

### Semester Schedule
[paste full content of session_plan.md here]

[For each of the 4 units, insert a unit block:]

[For each of the 4 themes in this unit:]

[After all 16 themes:]
```

**Rules:**
- Every `<!-- PAGE BREAK -->` comment becomes a CSS page break in the rendered PDF
- Preserve `★` characters for priority question badges
- Keep That's Life sections intact — do not summarise
- Table formatting must be valid markdown (pipe-separated)
- Do NOT include video filenames, file paths, or system metadata in the document

## Step 3 — Assemble the Student Edition markdown

Write `<output-dir>/module_handbook_student.md`.

Same structure as Lecturer Edition, with these differences:
- **Remove** all `*Answer:*` lines from Active Learning Questions
- **Remove** all `*Model answer:*` lines from SAQs
- **Remove** answer key markers (`✓`) from MCQ options
- **Replace** "Lecturer Edition" with "Student Edition" in the title block
- **Remove** the "Suggested timing" and "Session type" lines from each theme
- **Keep** all That's Life sections, objectives, glossary, and activities

## Step 4 — Copy the stylesheet

```bash
mkdir -p "<output_dir>"
cp <LEARNFORGE-TOOL-HOME>/reference/handbook.css "<output_dir>/handbook.css"
```

If that path doesn't exist, write the stylesheet directly. The canonical stylesheet is at:
`<LEARNFORGE-TOOL-HOME>/reference/handbook.css`

---

## Step 5 — Convert markdown to styled HTML

Use pandoc to convert each edition to a standalone HTML file with the stylesheet embedded:

```bash
# Lecturer edition
pandoc "<output_dir>/module_handbook_lecturer.md" \
  --standalone \
  --css "<output_dir>/handbook.css" \
  --metadata title="[module_title] — Lecturer Handbook" \
  -o "<output_dir>/module_handbook_lecturer.html"

# Student edition
pandoc "<output_dir>/module_handbook_student.md" \
  --standalone \
  --css "<output_dir>/handbook.css" \
  --metadata title="[module_title] — Student Handbook" \
  -o "<output_dir>/module_handbook_student.html"
```

Verify both HTML files exist and are non-zero:
```bash
ls -lh "<output_dir>"/*.html
```

---

## Step 6 — Render HTML to PDF via Chrome headless

```bash
CHROME="$HOME/.cache/hyperframes/chrome/chrome-headless-shell/linux-131.0.6778.85/chrome-headless-shell-linux64/chrome-headless-shell"

# Lecturer PDF
"$CHROME" \
  --headless \
  --no-sandbox \
  --disable-gpu \
  --print-to-pdf="<output_dir>/module_handbook_lecturer.pdf" \
  --print-to-pdf-no-header \
  "file://<output_dir>/module_handbook_lecturer.html"

# Student PDF
"$CHROME" \
  --headless \
  --no-sandbox \
  --disable-gpu \
  --print-to-pdf="<output_dir>/module_handbook_student.pdf" \
  --print-to-pdf-no-header \
  "file://<output_dir>/module_handbook_student.html"
```

**Note:** Chrome headless shell path includes the version number. If the path above doesn't exist, find the correct path with:
```bash
find ~/.cache/hyperframes/chrome -name "chrome-headless-shell" -type f 2>/dev/null | head -1
```

Verify both PDFs exist and are at least 50 KB:
```bash
ls -lh "<output_dir>"/*.pdf
```

If a PDF is smaller than 50 KB, it likely failed silently — check the HTML file for errors and re-render.

## Common Pitfalls

- **Missing theme files:** If fewer than 16 theme content files exist, assemble what's available and note which themes are missing in the cover page. Do not abort.
- **CSS not loading in PDF:** The `--css` path must be absolute. Use `realpath` to resolve if needed.
- **Chrome sandboxing error:** Always include `--no-sandbox` and `--disable-gpu` in WSL environments.
- **Page break in wrong place:** `<!-- PAGE BREAK -->` comments are converted to `<div class="page-break"></div>` by pandoc's HTML writer — confirm the CSS `.page-break { page-break-after: always; }` rule is present in handbook.css.
